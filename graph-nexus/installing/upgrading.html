    There are many ways of upgrading Nexus - this document covers two of the most common. Contact the Nexus team if you need any help with your upgrade process.

    Upgrading

    Nexus versioning#

    It’s worth understanding the difference between major and minor Nexus versions, because it affects the steps you should take before you upgrade. We use a format similar to semantic versioning, where releases are numbered in the format major.minor:

    • Major versions (e.g., x.0) are released roughly once a year. In exceptional cases, they may contain breaking changes.
    • Minor versions (e.g., x.1, x.2, etc.) are released regularly throughout the year. They contain backwards-compatible features and fixes.

    Before you upgrade#

    It's important to read the Release Notes for details of new and updated features, enhancements, and bug fixes. Also check the deprecated items that we plan to stop supporting in the next major release. You can check the details of your current version using GraphNexus.info() to work out what's changed.

    Before you upgrade to a major version, it’s also important to check for:

    • Breaking changes
    • End of support notices in the Release Notes

    If you can’t upgrade to the latest major version right away, you can always use a Long Term Availability (LTA) release.

    How to upgrade#

    Recommended way - for Nexus installed as an npm package#

    If you have installed Nexus 6.10 or later using our instructions for JavaScript, Angular, React, Vue, Webpack or Rollup, you have installed Nexus as a npm package using graph-nexus-<version>.tgz, which is our recommended installation method.

    To upgrade your package to the latest version, follow the steps to replace your existing graph-nexus-<version>.tgz package with the latest version and add it to your project:

    1. First, build the latest Nexus package (npm run build && npm pack in the Nexus repository).
    2. Go to your project directory and remove any older graph-nexus-<version>.tgz packages that are already in your project.
    3. Move the downloaded package in your project directory. Do not change the file name.
    4. Using a package manager such as npm or yarn, remove the old version and install the package again from inside your project's directory: 
      5. npm uninstall nexusgraph
npm install file:./graph-nexus-1.0.0.tgz
    5. To verify the upgrade was successful, run the following command from inside your project's directory: 
      6. node -p 'require("graph-nexus").info()'
    6. Run your compatibility tests in a developer environment before you deploy to production.

    Legacy installations - for applications using graph-nexus.umd.js#

    If you are using Nexus 6.9 or earlier, you have most likely installed Nexus as a UMD bundle by referring to graph-nexus.umd.js.

    This is now a legacy installation method and we recommend following our instructions for JavaScript, Angular, React, Vue, Webpack or Rollup to install Nexus as a npm package.

    If you want to keep using graph-nexus.umd.js and need to upgrade to the latest version, follow these steps to overwrite your existing files with the new versions:

    1. First, build the latest Nexus package (npm run build && npm pack in the Nexus repository).
    2. Unpack the graph-nexus-<version>.tgz archive. You can read more about this format and how to unpack it in the File Format Database.
    3. Locate the graph-nexus.umd.js file in the unpacked archive. This should be located in nexusgraph-7.5.0-6286156683/js/.
    4. Go to your project directory and replace your old graph-nexus.umd.js file with the new one.
    5. If you're using map mode or PDF export, you will also need to replace the following files and change any existing references to point to the new files:
      6. Old fileNew fileLocation in unpacked archiveComment
      leaflet.jsleaflet.jsgraph-nexus/assets/vendor/leaflet/Required for map mode
      pdfkit.standalone.jspdfkit.standalone.cjsnexusgraph-7.5.0-6286156683/pdf/Required for PDF export
      svg-to-pdfkit.jssvg-to-pdfkit.cjsnexusgraph-7.5.0-6286156683/pdf/Required for SVG to PDF export
    6. To verify the upgrade was successful, you can call GraphNexus.info() to show information about your Nexus environment.
    7. Run your compatibility tests in a developer environment before you deploy to production.

    Troubleshooting#

    Error in the console: Cannot find namespace 'GraphNexus'#

    If your TypeScript uses a Nexus namespace you could see this compilation error. For example:

    // Error: Cannot find namespace 'GraphNexus'
function labelValue(label: GraphNexus.LinkEndLabel) {}

    This is because prior to version 6.10 Nexus came as a UMD bundle with a global variable and namespace 'Nexus'.

    Nexus versions 6.10 and later come with both UMD and ESM bundles, and the TypeScript declaration has changed to make these bundles compatible with each other.

    Below are some suggestions how to fix this compilation error:

    Use a wildcard import#

    One way to fix the compilation error is to introduce a wildcard import at the top of your file to import Nexus types: 

    import GraphNexus, * as kl from "graph-nexus";

    And then later in the same file you can refer to this wildcard:

    function labelValue(label: kl.LinkEndLabel) {}

    You can read more in the Using Nexus type definitions section of our TypeScript documentation.

    Continue using graph-nexus.d.ts#

    If you don't need to access the latest Nexus type definitions, you can avoid this issue by continuing to use the graph-nexus.d.ts TypeScript declaration file that was used prior to version 6.10.

    This file will be forward compatible with newer releases until the next major version.
